# 生成 CPT 的提示词模板

照这个模板填空，模型就能一次出对的配方 + CPT。模板的每一格都对应我们踩过的坑——
不填的地方，我就得回来问你，或者自己猜（猜错就是"数据集配置错误"）。

## 一、完整模板（复制这段，替换 `{{}}`）

```text
【任务】按紫金 6.2 规范生成一份帆软 CPT 报表（数据库 PostgreSQL/Greenplum）。

【源表】
表：{{schema.table}}
字段与实测类型（pg_typeof 结果，重要）：
  {{col_a}}        {{varchar}}     -- {{YYYY-MM，如 2025-05}}
  {{col_b}}        {{numeric}}     -- {{指标值，可能为空}}
  {{col_c}}        {{boolean}}     -- {{true=汇总口径行，false=明细行}}
  {{col_d}}        {{varchar}}     -- {{公司简称}}
过滤语义：
  {{is_sum}}: 只保留 {{is_sum IS TRUE}} 的行（说明这句的业务含义：{{汇总口径行，明细行不参与合计}}）
  {{biz_month}}: 按 {{= '${biz_month}'}} 精确匹配；库里的值形如 {{2025-05}}
数据连接名：{{生产环境Greenplum}}（平台「数据连接」里真实存在的名字，不是占位）

【参数】
  {{biz_month}}  默认 {{2025-05}}   {{必传，来自平台搜索栏}}
  {{company}}    默认 {{全部}}      {{'全部' 或空串表示不过滤}}

【版式】
标题：{{产品产量指标月报（含环比）}}（横跨整表，合并单元格）
行维度（从上到下，标"分组"的相同值合并）：
  {{A 企业名称 = company_name_short，分组}}
  {{B 产品 = product_name，分组}}
  {{C 指标 = index_name(unit)，分组，单位拼进名字}}
度量：
  {{D 本期 = SUM(system_value)}}
  {{E 上期 = 上月同口径 SUM(system_value)}}
公式：
  {{F 环比 = (D-E)/E，E 为 0 时置空，格式 0.00%}}
合计：{{只合计 D/E 两列，其余留空}}
其它：冻结标题行与首列、底部预留 2 行空行、数字右对齐两位小数、
      {{本期环比为负标浅红、绝对值超 50% 标浅黄}}（不要就删掉这句）

【计算放在哪】
  {{能在 SQL 里算的（分组、汇总、过滤、上月自连接）放 SQL；跨格运算（环比、占比）放单元格公式}}

【输出】
  1. 配方 JSON（存 examples/recipe-{{xxx}}.json），先给配方再编译
  2. 编译命令与产物路径
  3. SQL 方言检查 + 6.2 规范自查的结论（有警告就列出来）
  4. 血缘摘要：每个数据格对应哪个源字段、做了什么加工
  5. 你不确定的地方直接列出来，不要编
```

## 二、填好的例子（就是上一份月报）

```text
【任务】按紫金 6.2 规范生成一份帆软 CPT 报表（PostgreSQL/Greenplum）。

【源表】
表：ads.ads_intern_bi_product_output_indicator_mf
字段与实测类型（pg_typeof）：
  biz_month          character varying   -- YYYY-MM，如 2025-05
  company_name_short character varying   -- 公司简称
  product_name       character varying   -- 产品
  index_name         character varying   -- 指标名
  unit               character varying   -- 单位，可能为空
  system_value       numeric             -- 指标值
  is_sum             boolean             -- true=汇总口径行
过滤语义：is_sum 必须为 true；biz_month 精确等于参数
数据连接名：生产环境Greenplum

【参数】
  biz_month 默认 2025-05（必传）
  company   默认 全部（'全部' 或空串 = 不过滤）

【版式】
标题：产品产量指标月报（含环比），合并 A1:F1
行维度：A 企业名称 / B 产品 / C 指标（都分组；指标名拼成 index_name(unit)）
度量：D 本期 = SUM(system_value)；E 上期 = 上月同口径
公式：F 环比 = (D-E)/E，E=0 置空，0.00%
合计：只合计 D、E
其它：冻结 + 底部 2 行空行 + 数字右对齐；环比<0 标浅红，|环比|>50% 标浅黄

【计算放在哪】上月自连接放 SQL，环比放单元格公式

【输出】配方 JSON → 编译 → 方言/规范结论 → 血缘摘要 → 不确定项单独列
```

## 三、最小版（赶时间就写这个）

```text
用 ads.ads_intern_bi_product_output_indicator_mf 出一份「按企业/产品看指标，含本期、上期、环比」
的分析表，PG，连接：生产环境Greenplum，参数 biz_month 默认 2025-05，套 6.2 规范。
is_sum 是 boolean，只要 true 的行。
```

这一版能跑，但我会按默认口径填：分组维度取「企业+产品+指标」、环比算 `(本期-上期)/上期`
除零置空、合计只合计度量列、不加密标色。**默认值与你的预期不一致时要明说**。

## 四、模板里为什么必须是这几格

| 格子 | 不填会怎样（都是实际踩过的） |
|---|---|
| 数据连接名 | 我用占位名 → 打开就报"数据集配置错误" |
| 列类型 | 布尔列写成 `= 1` → `operator does not exist: boolean = integer`；varchar 月份被当 date 处理 → `invalid input syntax` |
| 过滤语义（`is_sum` 这类标志列） | 我按"汇总行标记"过滤，若它其实是"指标可加性"，数据会缺一半 |
| 月份值格式 | 库里存 `2025-05-01` 还是 `2025-05`，决定用 `=` 还是 `LIKE`；用错不报错但查不到数 |
| 参数默认值 | 空默认值 + SQL 不容忍空 → 预览就炸；或者拿不到可预览的样例数据 |
| 行/列维度归属 | 指标该横铺（交叉表）还是竖排（分组明细），版式完全不同 |
| 计算放在哪 | 全塞 SQL → 报表里改不动；全塞公式 → 大数据量下逐格求值慢 |
| 规范 | 不写也会套 6.2（默认 `standard: "zjky"`），但字号/行高列宽/冻结/空行就按规范来，不另行商量 |

## 五、改现有模板 / 排查报错 的提示词

**改模板**（对应 `fr-cpt-edit`）：

```text
改 {{模板路径}}：
1. {{把标题改成 2025年产品产量月报}}
2. {{环比列加千分位？不，改成百分比两位小数}}
3. {{本期小于 100 的整行标黄}}
先 --plan 给我看影响哪些格子，我确认后再落盘。
```

要点：说清**改哪个格子/哪一类格子**（"环比列"比"F3"稳），说清**期望结果**，要求先 `--plan`。

**排查报错**（对应 `fr-cpt-analyze`）：

```text
{{模板路径}} 报"数据集配置错误"。
先跑 cpt_dump 看结构、cpt_analyze --dialect 看 SQL，把数据集 SQL 原样贴出来，
指出哪一处是类型/方言问题，给出可直接替换的写法。不要改模板文件。
```

要点：把**原始报错**贴全（数据集预览弹窗底部那行），"数据集配置错误"本身没有信息量。

## 六、我拿到不完整提示词时会先问的三个问题

按这个顺序问，基本一次问完：

1. **连接名**是什么（平台上真实存在的那个）？
2. 涉及到的**标志列/日期列的实测类型**（`pg_typeof` 跑一下，或告诉我 DDL）？
3. **版式意图**：指标要横铺还是竖排？要不要合计/占比/环比？

其余（字号、行高、冻结、空行、边框、对齐）不用问——6.2 规范已经定死。
