## 文字条款（逐条可查）

1. 字体统一微软雅黑；只有两种字号：表头 11 加粗，正文 10 不加粗。
2. 列宽通用 28mm；项目名称显示不全时按需调整，但调整后**同一表内列宽要一致**，换行尽量字数相近。
3. 行高 7mm；**相同报表不同页签**的行高列宽要一致。
4. 除标题外数字统一右对齐、右边缩进 3、数字不换行；小数位与千分位按业务方要求（千分位默认不要）。
5. 文字居中、左右缩进 3。
6. 标题行与标题列需**冻结**；最后一列标题列右侧列取消左边框（手工微调）。
7. 报表底部预留**两行空行**。
8. 权属企业不适用的指标：无填充底色 + 两道杠【--】，【--】居中。
9. 公式因数据原因算不出（无穷大）时置空。
10. 公司列头统一为【企业名称】。
11. 帆软工具栏背景白色（服务器默认即白色；模板单独设过才需要改回）。
12. 同比增加原因说明若整行合并，统一左对齐。
13. 填报表兼分析表：取数与公式默认底色 `E3F1F1`，用条件属性 `$op='view'` 转白，一套表两用。

## 自查

```bash
python ../fr-cpt/scripts/cpt_dump.py 模板.cpt --standard          # 分析表口径
python ../fr-cpt/scripts/cpt_dump.py 模板.cpt --standard --entry  # 填报表口径
```

检查器输出形如：

```
WARNING ZJ-STYLE: A1（标题/上侧表头）偏离规范：字号(pt) 应为 11，实际 12
WARNING ZJ-ROW-HEIGHT: 第 3 行行高 5.00mm，规范为 7.0mm
WARNING ZJ-FREEZE: 未设置标题行列冻结，应为 A3
```

规则编号与含义：

| code | 含义 |
|---|---|
| `ZJ-STYLE` | 单元格样式偏离该角色应有的样式 |
| `ZJ-STYLE-MISSING` | 有内容的格子没有样式 |
| `ZJ-ROW-HEIGHT` / `ZJ-COL-WIDTH` | 行高/列宽不统一或不等于 7mm/28mm |
| `ZJ-FREEZE` | 未冻结 |
| `ZJ-TAIL-BLANK` | 底部空行不足 2 行 |
| `ZJ-DASH-ALIGN` / `ZJ-DASH-FILL` | 【--】未居中 / 有填充底色 |
| `ZJ-VIEW-HIGHLIGHT` | 填报表取数格缺 `$op='view'` 条件属性 |
| `ZJ-COMPANY-HEADER` | 公司列头文案不是【企业名称】 |

角色是**推断**出来的（数据列之上=表头，其左=左侧表头，数值列=数字，其余=文字），
所以报告里会带单元格坐标，让人能核。用户如果知道真实版式，用 `roles` 显式钉住再查。

## 已知不确定项（别当定论）

1. **缩进的单位**：规范表写"3"，同行有 7mm/28mm，按毫米换算成 11px。若贵司实际按 px 填 3，
   改 `zjky.INDENT_MM = None; zjky.INDENT_PX = 3` 即可，其余不变。
2. **标题行样式**：规范只定义了上侧表头/左侧表头/正文三类，标题沿用上侧表头样式（11 加粗居中，
   `1D9390` 底）。若贵司标题另有规定，用 `set_style` 单独覆盖。
3. **`$op='view'` 的触发源**：平台把哪个参数映射成 `op`（URL 参数还是系统变量）不在规范文档里，
   生成的是条件属性本身；上线前要在平台上确认真实参数名。
4. 鼠标悬浮/超链接两行只给了底色，没有字形要求，未纳入检查。

## 落标登记（规范第 7 章）

报表上线前需在数据资产平台登记报表元数据（联系人：平台负责人）。

`report_name` 起成能对应业务的英文名，便于后续登记时对号。
