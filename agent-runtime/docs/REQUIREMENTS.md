# 需求总结（Requirements）

> 来源：2026-10-27 / 2026-10-28 与产品方的讨论。
> 本文件只记录**需求**；解决方案见 [ARCHITECTURE.md](ARCHITECTURE.md)、
> [../IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md)。
> 需求优先级：**Now（当前）→ Next（下一步）→ Later（后续）**。

---

## 1. 一句话目标

在**信息安全与保密**的前提下，把分散在不同开发人员手上的**业务逻辑与团队知识**沉淀为可复用的
**资产、文档和 Skill**，**强制统一开发规范**，并通过**可替换的开源编码 agent** 在 VS Code 中
反哺给开发者。

---

## 2. 背景与问题

| # | 问题 | 后果 |
|---|---|---|
| B1 | 开发分散、外包用工普遍，代码非标准化、少注释少释义 | 业务逻辑只存在个人脑中，交接/离职即丢失 |
| B2 | 业务知识散落在代码、提交、PR、聊天、文档里 | 无法系统归集、复用、盘点 |
| B3 | 开发规范不统一，靠人提醒 | 质量不稳定，review 成本高 |
| B4 | 团队 Skill 分散在个人/项目里 | 无法一键复用，重复造轮子 |
| B5 | 外部知识库（Confluence/飞书/SharePoint/内部 wiki）彼此割裂 | 检索成本高，知识无法联动 |
| B6 | 信息安全/保密要求高 | 不能把源码/业务逻辑交给外部云服务 |

---

## 3. 角色

| 角色 | 诉求 |
|---|---|
| 开发者 | 日常编码；接收资产相关知识/Skill；低摩擦确认捕获；不希望被"监控" |
| 知识评审 / 架构师 | 审核知识、文档、Skill；保证准确性和规范 |
| 管理员 / 安全 | 权限、审计、数据分级、模型/知识源接入、合规 |
| 团队负责人 | 资产盘点、文档覆盖、规范执行情况 |

## 4. 功能需求（FR）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-1 资产识别** | 代码头部注释声明资产编号（`@asset-id`），插件扫描并关联后端资产 | Now（已有 P1） | 打开文件能识别编号；编号由后端分配查重；一个编号可跨多文件 |
| **FR-2 知识挂载与反哺** | 知识挂在资产编号上；对话时按资产注入相关知识；只注入已批准知识；有 token 预算 | Next | 打开带编号的文件发消息，prompt 中包含该资产的知识；预算可配 |
| **FR-3 业务逻辑采集与文档生成** | 从提交/PR/会话/代码中抽取业务逻辑，生成文档草稿，人工评审后发布 | Next | 能对指定资产生成结构化文档草稿；有评审/发布状态 |
| **FR-4 规范强制** | 统一开发规范以"规则包"形式存在；CI/PR 门禁强制执行；agent 负责解释/修复 | Later | 违规代码在 CI 被拦；规则可由管理员维护；agent 能按规则修改 |
| **FR-5 团队 Skill 库** | 一键导入/导出 Skill；版本、权限、归属、兼容性；不绑定单一 agent | Next | 导入一个 Skill 包后，指定 agent 能使用；版本可回滚 |
| **FR-6 知识库接入** | 自主接入其他知识库系统，做权限映射、增量索引、检索 | Later | 至少接一个外部知识库；检索结果带权限过滤 |
| **FR-7 编码 agent** | 开源、可嵌入、具备一定编码能力；Codex 主、OpenCode 备；OpenClaw 弃用 | **Now** | 能在 VS Code/CLI 中完成读/改/搜/跑命令；可取消；无残留进程 |
| **FR-8 统一事件与捕获** | 文本、工具调用、文件变更、turn 结束统一事件；会话后生成知识建议，人工确认 | Now（事件）/ Next（捕获） | 事件完整；turn.end 必发；确认后知识入库 |
| **FR-9 审批与权限** | 文件限制在工作区；shell 命令 allowlist + 逐次审批；按资产/项目授权 | Now（基础）/ Later（RBAC） | 危险命令不会自动执行；越界路径被拒 |
| **FR-10 审计** | 记录谁在何时调用了什么工具、读了/改了什么、用了哪个模型 | Later | 可按人/资产/时间查询；日志脱敏 |
| **FR-11 客户端形态** | 只做 VS Code 插件；复用原生编辑器/diff/搜索/终端；不做额外前端 | **Now** | 无独立 Web IDE；聊天 + 原生 diff + TreeView/QuickPick |
| **FR-12 可替换性** | agent runtime、模型、知识源、Skill 都可替换；不被单一厂商锁死 | **Now**（runtime）/ Later（其他） | 换 runtime 不改上层；事件契约稳定 |

## 5. 非功能需求（NFR）

### 5.1 安全与保密（最高优先级）

- **部署（2026-10-28 调整）**：默认使用内网/私有云模型；**允许用户显式配置公网
  OpenAI-compatible 模型提供商**（内网/外网由用户选择）。公网模型属于显式例外，必须
  opt-in、界面告警、可审计；默认仍不出网。秘密级数据禁止出境、禁止进第三方 agent。
- **数据分级**：公开 / 内部 / 秘密；秘密级禁止出境、禁止进第三方 agent。
- **最小权限**：文件工具限制在 workspace；shell allowlist + 审批；RBAC（后续）。
- **审计**：工具调用、数据访问、模型调用可追溯；日志脱敏。
- **密钥**：不硬编码、不落盘明文、不传给不需要的子进程。
- **供应链**：开源许可证合规；pin 版本；保留 NOTICE；审查遥测/外联。
- **第三方 agent**：必须能关闭遥测/自动更新/云登录，并在断网环境验证。

### 5.2 网络与地域

- 默认部署在中国大陆内网；**不把** Anthropic/OpenAI 等外部云作为硬依赖。
- **模型提供商由用户配置（已拍板 2026-10-28）**：支持内网或公网 OpenAI-compatible
  提供商；公网模型默认关闭，需用户显式选择并确认数据出境风险。
- 模型优先国产/内网：Qwen3-Coder（首选）或 Qwen3-235B 系列；公网可作为无内网模型时的
  过渡/可选配置，不能作为默认。
- 任何跨境服务必须经过安全/法务评审；默认关闭。公网（含国内）模型仍属外部服务，
  需要审计与数据分级约束。
- 设计上保持模型/提供商可替换；Codex 需要 Responses API，OpenCode 使用 chat completions，
  配置层要能表达这一差异。

### 5.3 性能与可靠性

- 内网首 token 延迟、单 turn 耗时要有基线；可接受范围由 PoC 确定。
- 上下文窗口按 131k 规划；注入知识有预算（条数 + 字符数）。
- `maxSteps`、工具超时、turn 超时、输出截断必须可配。
- 取消后 5 秒内停止；Windows 无残留进程；`turn.end` 必发。

### 5.4 可维护性与扩展性

- 运行时适配层隔离：Codex/OpenCode 差异只在 adapter 内部。
- 不 fork 第三方 agent；进程集成；pin 版本；contract test。
- 知识/Skill 通过 MCP/平台 API 暴露，避免 prompt 硬拼和厂商锁定。
- 纯 Node/TS，核心不依赖 VS Code，可 CLI/单测。

### 5.5 可用性与组织

- 低摩擦：VS Code 内完成，不额外装 IDE/前端。
- 捕获需**明示、可关闭、可脱敏**；不能变成对开发者的监控。
- 对开发者有直接价值（知识反哺、文档、规范提示），否则采集推不动。
- 文档/Skill 需要评审流程，不能全自动入库。

### 5.6 平台与许可

- 开发机：Windows 11、Node 24、VS Code 1.85+、PowerShell 5.1（兼容，无 pwsh）。
- 开源许可：Codex Apache-2.0、OpenCode MIT；内部商用需保留 NOTICE。
- 交付形态：VSIX（VS Code 插件）+ 内网服务；不做独立安装器/Web 前端。

## 8. 约束与假设

- 默认推理来源为内网模型；用户可显式配置公网 OpenAI-compatible 提供商。
- Qwen3-Coder 是否可用待确认；公网模型（如 DeepSeek）可作为过渡选择。
- 只做 VS Code 客户端；不另做 Web/Electron 前端。
- OpenClaw 弃用；Codex/OpenCode 为当前 runtime 候选。
- 本阶段不做知识/Skill 注入；下一阶段做。
- 信息安全/保密优先于编码能力；外部云默认不可用。
- 代码分散、可能含外包人员；采集必须考虑隐私与授权。
- 维护人力有限：优先集成、少自研；核心平台自研。

---

## 9. 非目标

- ❌ 不做"最强的 coding agent"；agent 是商品。
- ❌ 不做多租户 SaaS/计费/复杂权限（后续再说）。
- ❌ 不做 Web IDE、文件树、编辑器、diff 面板（用 VS Code 原生）。
- ❌ 本阶段不做多 agent、并发会话、团队协作。
- ❌ 不做向量检索/语义 RAG（后续）。
- ❌ 不把 Claude Code/外部云作为核心依赖。
- ❌ 不 fork Codex/OpenCode，不复制其源码进仓库。
